# What the threads outside the render pool keep once their surfaces go

Evidence only, not part of the PR. The steps that re-measure the PR comment's tables, each script below in turn, and those of `heap/` are in [the comment](https://github.com/wcandillon/react-native-skia/pull/4362#issuecomment-6488946612).

- `RecorderTrimProbe.tsx` and `recorder-trim-probe.js`: the screen and its entry file. It makes and disposes 20 surfaces of 2048 × 2048 on the JS thread, then on the UI runtime and on a `createWorkletRuntime` runtime, then has the JS thread let go of 20 more in each of these ways: while it draws on every frame, disposed on the UI runtime, through `asImage()` images the UI runtime took, through snapshots taken into `MakeNull()` images, through snapshots shaders hold, as 20 snapshots of a canvas, and as `drawAsImage`'s surfaces left to the collector. It logs a `TRIM mark=<step>` line at each step, and a `TRIM memory` line with what the thread's recorders hold and Dawn's account of the device.
- `probe-memory.patch`: adds the readings the screen logs to `Skia.gpu`, for these builds only; it applies to #4353's head `234d6c026` and to this PR at `9409aa861`.
- `build-probe.sh <checkout> probe-memory.patch`: builds the example of a checkout at the commit to measure as an arm64 release APK whose bundle opens the screen, the patch applied and the screen copied in for the build only, and writes it beside itself as `recorder-trim-probe-<commit>.apk`.
- `run-probe.sh <serial> <apk> <folder>`, with `ANDROID_HOME` naming the Android SDK: installs and starts it, dumps the app's memory (`dumpsys meminfo` of its pid, and `dumpsys gpu --gpumem` from Android 12) at each step, and 10 s after Home.
- `bun summarize-probe.ts <folder>`: each step's readings; `bun compare-runs.ts <base folder>... -- <head folder>...`: a phone's table in the PR's comment, each value the median of the runs a side; `bun submit-table.ts <phone>=<base folder>+...,<head folder>+...`: the submit-cost table.
- `request-cost.cpp`: what the request a GPU submit now makes costs, against the same loop without it, built from the root of a checkout at the commit to measure: `g++ -std=c++20 -O2 -I packages/skia/cpp <this folder>/request-cost.cpp -o request-cost && ./request-cost`.
- `runs/<phone>/`: the three runs of each build on each phone, made in turn: #4353's head `234d6c026` on `main` `280986c10`, and this PR at `9409aa861`, built from `9c47166c1`, the local commit it was folded from, whose tree it has (the run folders carry that name). Each run keeps the phone's state before and after, the screen's log lines and its summary; `compared.md` and `runs/submit.md` are the comment's tables.
- `runs-0a6a1dd1e/`: the series the comment showed before, laid out as `runs/`: `main` `feee40afc` with #4353 at `10a60ae74`, and this PR at `0a6a1dd1e`, three runs of each on the Galaxy S23, the RedMagic NX809J and the Mi MIX 3.
- `heap/`: what a post to Android's present thread does with Java's heap full. `PresentPostProbe.tsx` and `present-post-probe.js` are the screen and its entry file; `evidence-heap-present.patch` (this PR at `9409aa861`) and `evidence-heap-present-d8f8f27c8.patch` (its earlier head, which posted through Java) let the screen hold the main thread in native code, fill Java's heap and post, and log what ran; the scenario is set with `adb shell setprop log.tag.SkiaProbeScenario <control|direct|trims>` before the launch.
- `apple/`: the trim of Apple's present thread, `RNSkPresentThread`, on a Mac, before #4410 replaced that thread with the C++ one for both platforms whose binding `ThreadTrimsTest` now checks. `present-thread-trim.mm` makes on the present thread the request for its trim that each present makes, with no GPU work, the trims' delay set to 200 ms and a counter in place of the trim, and exits 0 once a trim ran there while the thread was idle and another after a task that held it past the due time, none inside the task; its first lines give the command, from the root of a checkout. `f0544f4ca.log` and `2d8f7a327.log` are its output on this PR before and after it bound the thread's dispatcher to its run loop.
