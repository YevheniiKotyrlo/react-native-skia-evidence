Each scene is applied to a build for its bundle only:

```sh
git apply static-content-bench.patch    # or w1/cycle-check.patch
cd apps/example
npx react-native bundle --entry-file static-content-bench.js --platform android --dev false --minify true \
  --bundle-output dist/main.android.jsbundle --assets-dest dist/res
cd android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
```

`BENCH_PRESENTERS` (`none`, `canvas-texture`, `image-view`) limits the presenters the bench mounts; `BENCH_CYCLES` sets the cycle check's mounts per arm. On iOS the same bundles go into a Release build of the example.

## Steps

Each bench starts on launch and logs its readings, one `BENCH` line per measured window (`adb logcat -s ReactNativeJS`, or the device console on iOS).

- [`static-content-bench.patch`](static-content-bench.patch): 120 views of 40 points mounted and unmounted every 800 ms, each showing one image or one of 120 through a plain `View`, a `<Canvas>` or a `SkiaImageView`; then mounted under a parent whose opacity and scale animate; then given a new image every 800 ms. Each arm runs three passes of 9.6 s windows, every UI-thread frame read by a Reanimated frame callback (`BENCH probe … missedFrames=…`): a missed frame is a frame period of the window no callback ran in. The memory phase logs `BENCH memory-mounted` and `BENCH memory-unmounted` markers, at each of which I read `adb shell dumpsys meminfo <package>`. [`spread.py`](spread.py) turns the logs into the tables: `python spread.py S23=s23.log RedMagic=redmagic.log`.
- [`w1/cycle-check.patch`](w1/cycle-check.patch): the bench with 1,000 mount cycles per arm and Dawn's account of its allocator after each arm, as held and once asked to reduce, through [`w1/dawn-memory.patch`](w1/dawn-memory.patch), which adds that account to the native build. [`w1/idle-trace-before.patch`](w1/idle-trace-before.patch) and [`w1/release-trace.patch`](w1/release-trace.patch) log the render threads' idle runs and the poller's release rounds; [`w1/busy-after-request.patch`](w1/busy-after-request.patch) gives every render thread a 5 ms job 100 ms after the latest idle request, the race `RNSkIdleTaskSchedule` closes.
- [`probes.patch`](probes.patch): e2e probes of their own. `FirstPixel.probe` mounts one view at a time and captures every frame from the commit that mounts it until its pixels show, twelve times per presenter and size (`FIRST_PIXEL`, summed up by [`first-pixel.py`](first-pixel.py)); `Background.probe` sends the app to the background and back and compares a static canvas's frame and an image view's bitmap before and after; `ImageViews.probe` drives the example's image views page in Chromium (`IMAGE_VIEWS_WEB_PASSES`, summed up by [`summarize.py`](summarize.py)). The device probes run as the e2e specs do, from `packages/skia` with the example open on its tests screen (`E2E=true yarn test -i FirstPixel.probe`); the web one from the root, on a production bundle (`npx playwright test --config apps/example/playwright.config.ts ImageViews.probe`).
- [`MinifiedCapture.probe.spec.tsx`](MinifiedCapture.probe.spec.tsx), copied into `packages/skia/src/renderer/__tests__/e2e/`, writes the minified screens as captured to `CAPTURE_DIRECTORY`, an absolute path, since Jest runs in `packages/skia`; [`crop-capture.ts`](crop-capture.ts) crops their middles, at their own pixels. The even stripes' "before" is an October build of the app without the levels, the odd ones' the head with [`mutant-scaled-halving.py`](mutant-scaled-halving.py) applied, which makes each level with `createScaledBitmap`.
- [`ZonePlate.tsx`](ZonePlate.tsx), registered in `apps/example/src/Tests/Screens/index.ts` as `ZonePlate`, draws a 4096 × 4096 zone plate into an image view filling the screen; [`ZonePlateCapture.probe.spec.tsx`](ZonePlateCapture.probe.spec.tsx) writes it to `CAPTURE_DIRECTORY`. Its "before" ran with `PresentedImage.levelFor` returning 0, so that the view draws the bitmap itself.
- [`web-scale-paths.mjs`](web-scale-paths.mjs) times the web view's two ways of scaling an image larger than a canvas allows, in Playwright's Chromium on the checkout's CanvasKit: a full readback into a raster copy scaled on the CPU, against a WebGL render target of the encoded size; and draws a CPU image half again as wide as the GPU's largest texture on the GPU path: `node web-scale-paths.mjs <react-native-skia checkout> out.json [--gpu]`.
- [`OnScreenMinified.probe.spec.tsx`](OnScreenMinified.probe.spec.tsx), copied into `packages/skia/src/renderer/__tests__/e2e/`, shows the minified screens and captures the device's display as it shows each into `PROBE_OUTPUT`, with the command `CAPTURE_DISPLAY` names run with the capture's path appended (`pymobiledevice3 developer dvt screenshot`): the screen snapshot draws the layers on the CPU, which leaves Core Animation's filters out. [`read-display.mjs`](read-display.mjs) reads the test screen's middle in each capture as the spec's `readMiddleLuminance` reads a snapshot, and with `--crop` writes that middle at its own pixels: `node read-display.mjs <canvaskit-wasm bin/full folder> [--crop <folder>] <capture.png>...`. The iPad's "default filter" capture ran on a build of this PR without its content view's two `kCAFilterTrilinear` lines.
- [`ImageViewAccessible.tsx`](ImageViewAccessible.tsx), registered in `apps/example/src/Tests/Screens/index.ts` as `ImageViewAccessible`, shows an image view with `accessible` and an `accessibilityLabel`; [`ImageViewAccessibility.probe.spec.tsx`](ImageViewAccessibility.probe.spec.tsx), copied into `packages/skia/src/renderer/__tests__/e2e/`, reads the app's element tree from a WebDriverAgent runner serving the iOS device (`WDA_RUNNER_URL`, its `/source`) and expects the view's element accessible, carrying its label.
- [`ForceDarkCapture.probe.spec.tsx`](ForceDarkCapture.probe.spec.tsx), copied into `packages/skia/src/renderer/__tests__/e2e/`, writes the screen of a canvas above an image view to `CAPTURE_DIRECTORY`, run on a phone with force dark on (`adb shell setprop debug.hwui.force_dark true`, night mode on). Its "before" ran on October builds of this PR, one with `SkiaImageView` opting nothing out of force dark and one with the whole view opted out. [`force-dark/`](force-dark) holds `ee789a28f`'s captures: the Mi MIX 3's, whose MIUI darkens the app, and the RedMagic's, whose Android leaves the example's DayNight theme alone.
- [`ImageViewStress.probe.spec.tsx`](ImageViewStress.probe.spec.tsx), copied into `packages/skia/src/renderer/__tests__/e2e/`, loses the GPU device before each of `STRESS_CYCLES` screens of new images (12 where none is named) and expects every screen drawn once the device is replaced.
