# The GPU device made on a thread that never exits

Evidence only, not part of the PR. `main` is `8e30d2eed`, the PR `13601932c`; every build is a release build of the example.

- `goldfish-thread-exit-repro.cpp`: the emulator's guest Vulkan driver without Skia. A thread creates a Vulkan device, records a command buffer and submits it; then the main thread records, into that command buffer or into a new one on the same queue, while the first thread has exited or is kept alive. Its header has the build and run commands.
- `launch-alive.sh`: the launch check. It installs each APK, launches it a number of times, and reads 15 s after each launch whether the app is alive, its threads, and the header and top frames of every tombstone the device logged meanwhile.
- `launch/`: the check's output on the Android 10 (API 29) and Android 11 (API 30) emulator images, three launches of each build to the home screen and three to Android Views, and each `main` crash's tombstone.
- `../images/pr-4363-launch-recording.gif` and `../captures/pr-4363-launch-{main,this-pr}.mp4`: one launch of each build opening Android Views on the Android 11 image, recorded with `screenrecord`, cropped below the status bar.
- `recovery-thread-mutant.patch`: the PR with each replacement of a lost device made on a thread of its own that exits, as `main` makes it, the probe kept on the GPU thread.
- `device-loss/`: `Gpu.spec` on the Android 10 and 11 images with the PR and with the mutant, a file each: jest's report, the app's lines about its device with the thread each came from, and the mutant's tombstone. On Android 10 the e2e build outgrows the image's default heap growth limit at launch, so those runs set `dalvik.vm.heapgrowthlimit` to 64m and restarted the framework first.
- `e2e/`: CI's e2e selection (`CI=true yarn e2e` without the Paragraph suites, as CI's Android and iOS jobs run it) on a Galaxy S23, on an iPhone 12 Pro Max and on an Android 15 emulator image, `main` against the PR. That emulator renders on the host GPU rather than CI's `swangle_indirect`, where the device is lost at AHardwareBuffer imports on both builds; jest runs the previous run's failing suites first, so the PR ran in `main`'s suite order.
- `pacing/`: Breathe on a RedMagic (Android 16), `main` and the PR alternating, four rounds of two 10 s windows each, the first a warm-up left out for both builds: the display refresh rate of each window, the frames its layer showed (`dumpsys SurfaceFlinger --timestats`) and `dumpsys gfxinfo`.

To rerun the launch check, build the example's release APK for x86_64 from `main` and from the PR, start an Android 10 or 11 emulator image, and run `bash launch-alive.sh <serial> 3 <folder> <apk>...` with `ANDROID_HOME` set. For the driver alone, build and run `goldfish-thread-exit-repro.cpp` as its header says. For the device loss, start the example's e2e build (a `CI=true` bundle) on an Android 11 emulator image, or on Android 10 after `adb shell "su 0 setprop dalvik.vm.heapgrowthlimit 64m && su 0 stop && su 0 start"`, and, in `packages/skia`, run `E2E=true CI=true yarn jest -i src/renderer/__tests__/e2e/Gpu.spec.tsx`; with `recovery-thread-mutant.patch` applied the app dies after a replacement.
